**동적 계획법(Dynamic Programming, DP)** 은 큰 문제를 한 번에 풀기 어려울 때, 이를 **더 작은 하위 문제(Subproblem)로 나눈 뒤 그 계산 결과를 저장해 두고 재활용하여 전체 문제의 최적해를 구하는 알고리즘 기법**입니다. 쉽게 말해 *"기억하며 풀기"* 로 이해하면 직관적입니다.

## DP가 적용되기 위한 2가지 조건

모든 재귀 문제에 DP를 쓸 수 있는 것은 아닙니다. 아래 두 가지 성질을 모두 만족해야 DP가 성립합니다.

1. **중복되는 부분 문제 (Overlapping Subproblems)**: 동일한 작은 문제들이 여러 번 반복해서 호출됩니다. (예: `fib(5)`를 구할 때 `fib(3)`이 여러 갈래에서 중복 계산됨)
2. **최적 부분 구조 (Optimal Substructure)**: 큰 문제의 최적해가 작은 부분 문제들의 최적해를 조합해 구할 수 있습니다. (예: $A \to C$의 최단 경로는 $A \to B$ 최단 경로와 $B \to C$ 최단 경로의 합)

## Top-Down (메모이제이션) vs Bottom-Up (타뷸레이션)

| 구분 | Top-Down (Memoization) | Bottom-Up (Tabulation) |
| --- | --- | --- |
| **접근 방향** | 큰 문제 → 작은 문제 (재귀 호출) | 작은 문제 → 큰 문제 (`for` 반복문) |
| **상태 저장** | 필요할 때만 계산해 캐시(`Map`/`Array`)에 기록 | 테이블(`dp[]`)을 바닥부터 순서대로 모두 채움 |
| **장점** | 점화식을 직관적으로 옮기기 쉬움, 불필요한 상태 생략 | 재귀 호출 스택 오버헤드·Stack Overflow 위험 없음 |
| **단점** | 깊은 재귀 시 콜 스택 한계 주의 | 모든 하위 상태를 방문하게 될 수 있음 |

### 예제 1: 피보나치 수열로 비교하기

단순 재귀는 $O(2^N)$의 지수 시간이 걸리지만, DP를 적용하면 **$O(N)$** 으로 줄어듭니다.

```js
// 1. Top-Down (Memoization)
function fibMemo(n, memo = new Map()) {
  if (n <= 1) return n;
  if (memo.has(n)) return memo.get(n);

  const result = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
  memo.set(n, result);
  return result;
}

// 2. Bottom-Up (Tabulation + 공간 최적화 O(1))
function fibTab(n) {
  if (n <= 1) return n;
  let prev2 = 0;
  let prev1 = 1;

  for (let i = 2; i <= n; i++) {
    const curr = prev1 + prev2;
    prev2 = prev1;
    prev1 = curr;
  }
  return prev1;
}
```

## DP 문제로 사고하는 4단계 프레임워크

실전 코딩 테스트나 최적화 문제에서 DP를 떠올리고 구현하기까지 막막할 때는 다음 순서로 접근하면 좋습니다.

### 1단계: 완전 탐색(재귀)으로 점화식 세우기

처음부터 최적화된 배열 구조를 짜려 하지 말고, 먼저 "현재 상태에서 어떤 선택지들이 있는가?"를 완전 탐색 재귀 함수로 정의합니다.

### 2단계: 상태(State) 정의하기

재귀 함수의 매개변수 중 **결과를 결정짓는 핵심 상태가 무엇인지** 명확히 정의합니다.
- 예: *"인덱스 `i`까지 고려했을 때, 남은 용량 `w`로 얻을 수 있는 최대 가치"* → `dp[i][w]`

### 3단계: 기저 조건(Base Case)과 점화식(Transition) 확정

더 이상 쪼갤 수 없는 종료 조건(예: `dp[0] = 0`)과, 이전 상태로부터 다음 상태를 구하는 관계식을 코드로 옮깁니다.

### 예제 2: 최소 동전 개수 구하기 (Coin Change)

금액 `amount`를 만들기 위해 필요한 최소 동전 개수를 구하는 문제입니다. 각 금액 `x`에 대해 모든 동전 `coin`을 써 보는 점화식 $dp[x] = \min(dp[x], dp[x - coin] + 1)$ 을 세울 수 있습니다.

```js
function minCoins(coins, amount) {
  const INF = amount + 1;
  const dp = new Array(amount + 1).fill(INF);
  dp[0] = 0;

  for (let x = 1; x <= amount; x++) {
    for (const coin of coins) {
      if (x - coin >= 0) {
        dp[x] = Math.min(dp[x], dp[x - coin] + 1);
      }
    }
  }

  return dp[amount] === INF ? -1 : dp[amount];
}

console.log(minCoins([1, 2, 5], 11)); // 3 (5 + 5 + 1)
```

### 4단계: 공간 복잡도 최적화 검토

`dp[i]`가 직전 행 `dp[i - 1]`이나 직전 몇 개의 값에만 의존한다면 2차원 배열을 1차원 배열이나 몇 개의 변수로 줄여 메모리 사용량을 크게 낮출 수 있습니다.

## 핵심 요약

- DP는 **중복 부분 문제**와 **최적 부분 구조**가 있을 때 이전 계산 결과를 저장해 $O(2^N)$을 다항 시간으로 줄이는 기법입니다.
- 문제를 만나면 **상태 정의 → 점화식 도출(재귀) → 메모이제이션/타뷸레이션 전환** 순서로 단계를 밟으면 복잡한 DP 문제도 체계적으로 풀 수 있습니다.

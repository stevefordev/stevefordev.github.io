클로저(Closure)는 JavaScript를 다루는 모든 코드 속에 이미 녹아 있지만, 원리를 정확히 모른 채 작성하면 원인 모를 상태 버그나 메모리 누수에 빠지기 쉽습니다.

> [!NOTE]
> **클로저(Closure)** 란 함수와 그 함수가 선언될 당시의 **렉시컬 환경(Lexical Environment)** 이 결합된 개념입니다. 즉, 내부 함수가 자신이 선언된 외부 함수의 스코프를 기억하여, **외부 함수가 반환되어 실행 컨텍스트가 종료된 뒤에도 그 스코프 내 변수에 접근할 수 있는 성질**을 말합니다.

## 클로저는 어떻게 동작하는가?

```js
function createCounter() {
  let count = 0; // 외부 함수의 지역 변수

  return function increment() {
    count += 1;
    return count;
  };
}

const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
```

일반적으로 `createCounter()` 실행이 끝나면 지역 변수 `count`는 스택에서 사라져야 합니다. 하지만 반환된 `increment` 함수가 `[[Environment]]` 내부 슬롯을 통해 `createCounter`의 렉시컬 환경을 계속 참조하고 있기 때문에, **가비지 컬렉터(GC)가 `count`를 수거하지 않고 힙(Heap)에 유지**합니다.

## 단골 함정: 반복문과 비동기 콜백

클로저를 이해하지 못했을 때 가장 자주 마주치는 버그 패턴입니다.

```js
for (var i = 0; i < 5; i++) {
  setTimeout(() => {
    console.log(i);
  }, i * 100);
}
// 결과: 5, 5, 5, 5, 5
```

`setTimeout`의 콜백 5개가 실행되는 시점은 이미 `for` 루프가 모두 끝나 `i`가 `5`가 된 뒤입니다. 게다가 `var i`는 함수/전역 스코프에 **단 하나만 생성**되므로, 5개의 클로저가 모두 동일한 `i`를 공유합니다.

### 해결 방법 1: 과거 방식 — IIFE(즉시 실행 함수 표현식)

블록 스코프가 없던 ES5 시절에는 반복마다 새 함수 스코프를 만들어 값을 가두었습니다.

```js
for (var i = 0; i < 5; i++) {
  (function (captured) {
    setTimeout(() => {
      console.log(captured);
    }, captured * 100);
  })(i);
}
```

### 해결 방법 2: 모던 방식 — `let` 블록 스코프

`for` 문 조건부에 `let`을 사용하면 JavaScript 엔진이 **반복마다 새로운 렉시컬 환경을 생성하고 `i`를 바인딩**해 줍니다.

```js
for (let i = 0; i < 5; i++) {
  setTimeout(() => {
    console.log(i);
  }, i * 100);
}
// 결과: 0, 1, 2, 3, 4
```

## 실무에서 유용한 클로저 활용 패턴

### 1. 상태 은닉 (Private State)

외부에서 직접 수정할 수 없는 안전한 상태를 유지하고, 허용된 메서드를 통해서만 값을 변경하도록 제한합니다.

```js
function createBankAccount(initialBalance = 0) {
  let balance = initialBalance;

  return {
    deposit(amount) {
      if (amount <= 0) throw new Error("입금액은 0보다 커야 합니다.");
      balance += amount;
      return balance;
    },
    getBalance() {
      return balance;
    },
  };
}

const account = createBankAccount(1000);
console.log(account.deposit(500)); // 1500
console.log(account.balance);      // undefined (직접 접근 불가)
```

### 2. 설정 고정 및 커링 (Partial Application)

```js
const createLogger = prefix => message => {
  console.log(`[${prefix}] ${message}`);
};

const apiLog = createLogger("API");
apiLog("GET /users 200 OK"); // "[API] GET /users 200 OK"
```

### 3. 메모이제이션 (Memoization)과 디바운싱 (Debouncing)

React의 훅(Hooks) 원리나 이벤트 최적화에 쓰이는 `debounce` 역시 클로저로 타이머 ID나 캐시 `Map`을 기억하는 대표 사례입니다.

```js
function debounce(fn, delay) {
  let timerId = null;

  return (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), delay);
  };
}
```

## 주의점: 클로저와 메모리 누수

클로저는 참조하는 외부 변수를 메모리에서 해제하지 못하게 막습니다. 만약 더 이상 필요하지 않은 거대한 DOM 요소나 대용량 배열을 클로저 내부에서 참조한 채 이벤트 리스너를 제거하지 않으면 **메모리 누수(Memory Leak)** 로 이어집니다.

- 클로저 내부에서는 **필요한 최소한의 값만 참조**하세요.
- 더 이상 사용하지 않는 이벤트 리스너나 타이머는 `removeEventListener` / `clearInterval`로 반드시 정리해야 클로저 참조도 함께 해제됩니다.

## 핵심 요약

- 클로저는 **함수가 선언된 렉시컬 스코프를 기억해 외부 함수 종료 후에도 변수에 접근하는 메커니즘**입니다.
- 비동기 반복문 문제는 `let`의 반복당 스코프 바인딩으로 깔끔하게 해결됩니다.
- 상태 은닉, 팩토리 함수, 디바운스/쓰로틀, 캐싱 등에 핵심적으로 활용되지만, 불필요한 참조가 남지 않도록 수명 주기를 관리해야 합니다.

서버를 실제 운영 환경에 배포하면 `console.log()`만으로는 장애 원인을 추적하기 어렵습니다. 언제, 어떤 요청에서, 어떤 심각도의 문제가 발생했는지 파악하고 로그 파일이 디스크를 가득 채우지 않도록 관리하려면 전용 로깅 라이브러리가 필수입니다.

Node.js 생태계에서 오랜 기간 표준처럼 쓰이는 **Winston** 의 최신 v3 API 기준으로 실무에 바로 적용할 수 있는 로깅 구성을 정리합니다.

## 설치하기

```bash
npm install winston winston-daily-rotate-file
```

> [!NOTE]
> 과거 글이나 튜토리얼에서 파일 시스템을 다루기 위해 `npm install fs`를 안내하는 경우가 간혹 있지만, **`fs`는 Node.js 기본 내장 모듈(`node:fs`)** 이므로 별도로 npm에서 설치해서는 안 됩니다.

## Winston v3 기본 설정과 로그 레벨

Winston v3부터는 과거의 `new winston.Logger()` 생성자 대신 **`winston.createLogger()`** 와 조합 가능한 **`format` 파이프라인**을 사용합니다.

기본 npm 로그 레벨은 우선순위 숫자가 낮을수록 심각도가 높은 **7단계**로 구성되어 있습니다.

```text
{ error: 0, warn: 1, info: 2, http: 3, verbose: 4, debug: 5, silly: 6 }
```

예를 들어 `level: "info"`로 설정하면 `info`(2), `warn`(1), `error`(0)만 기록되고 `debug`(5) 이하는 무시됩니다.

```js file="logger.js"
import winston from "winston";

const { combine, timestamp, printf, colorize, errors, json } = winston.format;

const devFormat = combine(
  colorize(),
  timestamp({ format: "YYYY-MM-DD HH:mm:ss" }),
  errors({ stack: true }),
  printf(({ timestamp, level, message, stack, ...meta }) => {
    const extra = Object.keys(meta).length ? ` ${JSON.stringify(meta)}` : "";
    return `${timestamp} [${level}]: ${stack ?? message}${extra}`;
  })
);

const prodFormat = combine(
  timestamp(),
  errors({ stack: true }),
  json() // 운영 환경에서는 ELK/CloudWatch/Datadog 수집을 위해 JSON 구조화 로깅 권장
);

export const logger = winston.createLogger({
  level: process.env.NODE_ENV === "production" ? "info" : "debug",
  format: process.env.NODE_ENV === "production" ? prodFormat : devFormat,
  transports: [new winston.transports.Console()],
});
```

```js
logger.info("Server started", { port: 3000 });
logger.error("Database connection failed", new Error("ECONNREFUSED"));
```

## 파일 저장과 날짜별 로그 로테이션

서버 로그를 단일 파일에 계속 쌓으면 수 GB까지 커져 열기조차 힘들어집니다. **`winston-daily-rotate-file`** 트랜스포트를 결합하면 날짜별 파일 분할, 최대 용량 제한, 보관 기한 자동 삭제, 압축까지 깔끔하게 처리할 수 있습니다.

```js file="logger-with-rotate.js"
import fs from "node:fs";
import path from "node:path";
import winston from "winston";
import DailyRotateFile from "winston-daily-rotate-file";

const logDir = path.resolve(process.cwd(), "logs");
if (!fs.existsSync(logDir)) {
  fs.mkdirSync(logDir, { recursive: true });
}

const { combine, timestamp, errors, json } = winston.format;

export const logger = winston.createLogger({
  level: process.env.NODE_ENV === "production" ? "info" : "debug",
  format: combine(timestamp(), errors({ stack: true }), json()),
  transports: [
    // 모든 info 이상 로그 (일별 로테이션 + 14일 보관 + gzip 압축)
    new DailyRotateFile({
      dirname: logDir,
      filename: "app-%DATE%.log",
      datePattern: "YYYY-MM-DD",
      zippedArchive: true,
      maxSize: "20m",
      maxFiles: "14d",
      level: "info",
    }),
    // 에러 로그만 별도 파일로 분리해 장애 추적 속도 향상
    new DailyRotateFile({
      dirname: path.join(logDir, "error"),
      filename: "error-%DATE%.log",
      datePattern: "YYYY-MM-DD",
      zippedArchive: true,
      maxSize: "20m",
      maxFiles: "30d",
      level: "error",
    }),
  ],
});

if (process.env.NODE_ENV !== "production") {
  logger.add(
    new winston.transports.Console({
      format: winston.format.combine(
        winston.format.colorize(),
        winston.format.simple()
      ),
    })
  );
}
```

## 운영 환경 로깅 모범 사례

1. **구조화 로깅(JSON) 사용**: 문자열을 이어 붙이기보다 `{ requestId, userId, latencyMs }` 같은 메타 필드를 JSON으로 남기면 추후 로그 분석 도구에서 필터링·집계가 쉬워집니다.
2. **민감 정보 마스킹**: 비밀번호, JWT 토큰, 카드 번호 등 개인정보가 로그에 평문으로 찍히지 않도록 주의하세요.
3. **컨테이너(Docker) 환경이라면 표준 출력 우선**: 컨테이너 기반 인프라에서는 파일 저장 대신 `Console` 트랜스포트(`stdout`/`stderr`)로 JSON 로그를 내보내고, 호스트의 로그 에이전트(Fluent Bit, CloudWatch Agent 등)가 수집하도록 구성하는 것이 표준입니다.

## 핵심 요약

- Winston v3에서는 `winston.createLogger()`와 `format.combine()`으로 환경별 포맷(개발용 컬러 텍스트 vs 운영용 JSON)을 분리할 수 있습니다.
- 서버 디스크에 로그를 남길 때는 `winston-daily-rotate-file`로 용량(`maxSize`)과 보존 기간(`maxFiles`)을 반드시 제한하세요.

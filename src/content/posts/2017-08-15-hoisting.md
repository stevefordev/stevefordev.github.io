JavaScript 코드를 위에서 아래로 한 줄씩 실행한다고만 생각하면 예상치 못한 `undefined`나 `ReferenceError`를 마주치게 됩니다. 이러한 현상의 핵심에는 **실행 컨텍스트의 생성 단계와 호이스팅(Hoisting)**이 있습니다.

> [!NOTE]
> **호이스팅(Hoisting)** 이란 물리적으로 코드가 파일 맨 위로 이동하는 것이 아니라, JavaScript 엔진이 코드를 실행하기 전 **실행 컨텍스트 생성(Creation) 단계에서 현재 스코프 내의 식별자 선언 정보를 미리 메모리에 등록**하기 때문에 선언문 이전에 참조가 가능한 것처럼 보이는 현상입니다.

## 실행 컨텍스트의 2단계 동작

JavaScript 엔진은 스코프(전역 또는 함수)에 진입할 때 두 단계를 거칩니다.

1. **생성 단계 (Creation Phase)**: 스코프 내부의 변수·함수 선언을 스캔해 Lexical Environment(환경 레코드)에 등록합니다.
2. **실행 단계 (Execution Phase)**: 코드를 위에서 아래로 실행하며 값 할당(`=`)과 함수 호출을 수행합니다.

## 변수 호이스팅: `var` vs `let` / `const`

### `var`의 경우: 선언과 동시에 `undefined`로 초기화

```js
console.log(a); // undefined (에러가 나지 않음)
var a = 2;
console.log(a); // 2
```

엔진 관점에서 위 코드는 아래와 같은 순서로 처리됩니다.

```js
// 생성 단계: var a 등록 및 undefined 초기화
// 실행 단계:
console.log(a); // undefined
a = 2;          // 할당만 실행 단계에서 수행
console.log(a); // 2
```

### `let`과 `const`의 경우: TDZ (Temporal Dead Zone)

흔히 "`let`과 `const`는 호이스팅되지 않는다"고 오해하기 쉽지만, **실제로는 호이스팅됩니다.** 다만 생성 단계에서 선언만 등록될 뿐 **`undefined`로 초기화되지 않고, 선언문에 도달할 때까지 일시적 사각지대(TDZ)에 놓입니다.**

```js
const x = "outer";

{
  // 만약 let이 호이스팅되지 않았다면 바깥의 "outer"가 출력되어야 하지만,
  // 블록 내 let x가 이미 호이스팅되어 TDZ에 있으므로 ReferenceError가 발생합니다.
  console.log(x); // ReferenceError: Cannot access 'x' before initialization
  let x = "inner";
}
```

## 함수 호이스팅: 선언문 vs 표현식

함수를 정의하는 방식에 따라 호이스팅 결과가 완전히 달라집니다.

### 1. 함수 선언문 (Function Declaration)

생성 단계에서 **함수 이름과 본문 전체가 함께 메모리에 등록**되므로 선언 이전에도 정상 호출할 수 있습니다.

```js
sayHello(); // "Hello!"

function sayHello() {
  console.log("Hello!");
}
```

### 2. 함수 표현식 (Function Expression)

변수에 함수 값을 할당하는 형태이므로 **변수 호이스팅 규칙**을 따릅니다.

```js
// greet(); // var라면 TypeError: greet is not a function
// greetLet(); // let/const라면 ReferenceError

var greet = function () {
  console.log("Hi");
};

const greetLet = () => {
  console.log("Hi");
};
```

## 퀴즈로 확인하는 호이스팅 우선순위

같은 이름으로 변수와 함수 선언문이 공존하면 어떻게 동작할까요?

```js
foo(); // 출력 결과는?

function foo() {
  console.log(1);
}

var foo = function () {
  console.log(2);
};

function foo() {
  console.log(3);
}
```

**정답은 `3`입니다.** 실행 순서를 단계별로 풀어보면 명확합니다.

1. **생성 단계**:
   - `function foo() { console.log(1); }` 등록
   - `var foo`는 이미 `foo`가 존재하므로 무시됨
   - 뒤이은 `function foo() { console.log(3); }`가 기존 `foo`를 덮어씀
2. **실행 단계**:
   - 첫 줄의 `foo()`가 실행되어 `3`을 출력
   - 이후 `foo = function() { console.log(2); }`가 할당되므로, 이 줄 아래에서 `foo()`를 다시 호출하면 그때부터 `2`가 출력됨

## 실무 가이드

- `var` 대신 `const`와 `let`을 사용하면 TDZ 덕분에 선언 전 변수 접근 버그를 즉시 `ReferenceError`로 잡아낼 수 있습니다.
- 변수와 함수는 가능하면 **사용하기 전 상단에 명확히 선언**하여 코드의 읽는 순서와 실행 순서가 일치하도록 작성하는 것이 가장 좋습니다.
